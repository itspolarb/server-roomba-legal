Data Retention

Operational records are kept only as long as they remain useful for the feature, safety, or recovery.

The running bot performs retention cleanup automatically. A server’s configuration may specify shorter periods where supported.

Records kept until changed or removed

Current server configuration, module state, role and channel mappings, active ticket data, moderation cases, published verification policies and acceptances, active automations, birthdays, custom tags, and similar feature state remain while needed to provide the configured feature or preserve required history.

Ticket transcripts and moderation cases are intentionally durable because server staff may need them later. Server managers should limit access to those records.

Backups

Automated SQLite backups use a WAL-safe process, integrity verification, rotation, and retention. Backups exist for operational recovery and may briefly preserve data after it has been removed from the live database. Expired backups are rotated out.

Deletion and departure

Authorized server managers can delete server-specific data using the bot’s protected controls. Removing the bot alone prevents new activity but may not immediately remove existing records. Where deletion cannot be completed through Discord, contact thepolarbearr@gmail.com with the server ID.
